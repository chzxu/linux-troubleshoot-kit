# Git 版本控制实战

> 10 个动手实验，从三棵树模型到 reflog 救火。
> 每个实验都在你自己的仓库里真做一遍，做完打勾。

## 为什么单独开这个目录

Git 不是"会用几条命令"就够的。真实场景里：
- 误删了分支怎么救
- 提交历史乱成一团怎么整理
- 两个人改同一个文件怎么合
- 怎么找"是哪次提交引入了 bug"

**这些都不是看文档能学会的，必须真做一遍。**

## 怎么学

每个实验一个文件：```lab-01-xxx.md```、```lab-02-xxx.md``` ...

每个文件的结构固定：

| 段落 | 内容 |
|---|---|
| 目标 | 这个实验练什么 |
| 前置 | 需要先完成哪个实验 |
| 动手 | 一步一步的命令，直接复制执行 |
| 观察 | 每步应该看到什么，为什么 |
| 验收 | 做到什么算过关 |
| 坑 | 我实际踩过的 |

**规矩：不跑不算学完。**

## 十个实验

| # | 主题 | 你会搞明白什么 | 验收标准 |
|---|---|---|---|
| **01** | 三棵树与第一个提交 | 工作区 / 暂存区 / 版本库到底是什么 | 能说清 git add 之后文件在哪 |
| **02** | 看懂一次提交 | commit 里存的是什么 | 用 git show 读出某次提交改了哪几行 |
| **03** | 撤销的三种姿势 | 改错了、add 错了、commit 错了分别怎么退 | 三种误操作各自救回来一次 |
| **04** | 分支的本质 | 分支只是一个指针，HEAD 是什么 | 用 git log --graph 解释分支指向 |
| **05** | 合并：FF 与三方合并 | 什么时候是快进，什么时候要产生合并提交 | 各制造一次并说清区别 |
| **06** | 冲突：故意制造并解决 | 冲突标记长什么样，怎么手工合 | 解决一次真实冲突并提交 |
| **07** | Rebase 整理历史 | rebase 和 merge 到底差在哪 | 把 3 个零碎提交压成 1 个 |
| **08** | 裸仓库模拟远程协作 | 远程仓库到底是什么，push/fetch/pull 的区别 | 两个本地仓库通过裸仓库同步成功 |
| **09** | 救火：reset / reflog / stash | 为什么说 reflog 是后悔药 | 删掉一个分支后把它恢复回来 |
| **10** | 进阶：tag / bisect / hooks | 打版本、二分找 bug、提交前自动检查 | 用 bisect 找出引入问题的那次提交 |
