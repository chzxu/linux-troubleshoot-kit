# 案例 1–5 总结

> 五篇案例不是五个孤立的知识点，是**一条从文件系统走到网络连接失败的排查路径**。
> 这份总结把它们压成一张图、一张表、一套手法。

---

## 一、五个故障分别在哪一层

```text
┌─────────────────────────────────────────────┐
│ 05 连接失败    refused（收到 RST） vs timeout（什么都没有）  │  ← 传输层
├─────────────────────────────────────────────┤
│ 04 名称解析    dig（只问 DNS） vs getent（走 nsswitch）      │  ← 名字→地址
├─────────────────────────────────────────────┤
│ 03 端口占用    ss（全机监听） vs lsof（指定端口）            │  ← 进程层
├─────────────────────────────────────────────┤
│ 02 空间没释放  目录项删了，inode 还被进程持有                 │  ← 文件系统层
│ 01 基线        "变大→升→删→落"这条链路完整                 │
└─────────────────────────────────────────────┘
```

**越往上，越接近用户看到的报错；越往下，越接近真正的原因。**

## 二、五篇背后的同一个主题

五篇里有**三对"同源不同果"**——同一个事实，两条路径，结论不一样：

| 对撞 | 一个再说 | 另一个在说 | 差在哪 |
|---|---|---|---|
| **01/02 · `df` vs `du`** | 文件系统统计：还剩多少块 | 遍历目录：每个文件多大 | `df` 看的是**已分配块**，`du` 看的是**目录里还能数到的文件**——被删除但被持有的文件，`du` 数不到，`df` 算得到 |
| **03 · `ss` vs `lsof`** | 全机所有监听端口 | 某个端口上的所有连接 | 一个横向扫，一个纵向挖 |
| **04 · `dig` vs `getent`** | 直接构造 DNS 查询包 | 调 `getaddrinfo()`，走 NSS | `dig` **不读** `/etc/hosts`；程序读 |
| **05 · refused vs timeout** | 对方回了一个 RST | 什么都没回 | 一个**有证据**，一个**没证据** |

**一句话：先问清楚「我这个工具看的是哪份数据」，再问「结论为什么不一样」。**

## 三、四条可以直接背走的结论

### 1. 空间不释放，先看谁还开着它

```bash
lsof +L1        # +L1 = 链接数小于 1 的文件
```

输出的三个特征一眼破案：`NLINK 0`、名字后面带 `(deleted)`、`COMMAND` 是被谁持有。

**根因**：`rm` 删的只是目录项，inode 要等最后一个持有者关闭才释放。

### 2. 端口被占，两个工具对比看

| | `ss -tulpn` | `lsof -i :8080` |
|---|---|---|
| 看什么 | 全机监听端口 | 指定端口的**所有连接**（含已建立） |
| 端口显示 | 加 `-n` 才是数字 | 默认解析成服务名（`http-alt`） |
| 适合 | "这机器开了什么" | "谁占着 8080" |

**坑**：`kill` 之后能不能立刻重启，取决于**有没有 TIME_WAIT 连接残留**——必须先建立过连接才会有。

### 3. 排查 DNS，用 `getent` 不用 `dig`

- `dig` = 直接发 DNS 查询包，**不读** `/etc/hosts`，**不走** nsswitch
- `getent` = 调 `getaddrinfo()`，**和你的程序走同一条路**

**程序看到的和 `dig` 看到的不一样时，先 `grep 域名 /etc/hosts`。**

### 4. refused 和 timeout 的方向相反

| | 谁在说话 | 排查方向 |
|---|---|---|
| **refused** | 对方（回了 RST） | 往**对方服务**查：没监听？端口写错？ |
| **timeout** | 谁都没说话 | 往**路上**查：防火墙 DROP？路由？对端关机？ |

**会说话的好办，不理你的才要命。**

## 五、从症状出发的判断顺序

```text
用户说"连不上"
   │
   ├─ 秒回、报 refused ──────→ 对方在，服务没起 / 端口错 → 查 03、05
   │
   ├─ 卡几秒、报 timeout ────→ 路上有问题 → 查 05（iptables DROP / 路由）
   │
   ├─ 报"找不到主机" ───────→ 名字没解析出来 → 查 04（getent 先，hosts 次）
   │
   └─ 能连但服务报错 ───────→ 不是网络问题，往下查应用（05 的下一层）
```

**先分岔，再深入。别一上来就 `ping`。**

## 六、命令速查（五篇合并去重）

| 命令 | 干什么 | 出自 |
|---|---|---|
| `df -h` | 各分区使用率 | 01 |
| `du -x --max-depth=1 / \| sort -rh HEAD` | 找大目录，不跨文件系统 | 01 |
| `lsof +L1` | 找"已删除但仍被持有"的文件 | 02 |
| `ss -tulpn` | 全机监听端口 + 进程 | 03 |
| `lsof -i :端口` | 指定端口被谁占 | 03 |
| `ss -tan` | 所有 TCP 连接（看 TIME_WAIT） | 03 |
| `dig 域名 +short` | 直接问 DNS | 04 |
| `getent ahostsv4 域名` | 和程序一致地解析 | 04 |
| `grep 域名 /etc/hosts` | 确认是否被本地覆盖 | 04 |
| `curl -sv --connect-timeout 3 URL` | 看连接失败的确切原因 | 05 |
| `tcpdump -ni any port 9` | 看 SYN 之后有没有 RST | 05 |
| `ip route` / `ping -c2 IP` | 找网关 / 看对面活没活 | 05 |
