## 二、Docker / K8s / Pod 是什么关系

（用你自己的话讲三层。写完读一遍：没学过的人能不能看懂？）

- Docker 负责：将应用和环境打包，让应用在单机上跑起来
- K8s 负责：让这些包能够在几十台机器上调度、扩容、自愈、发布
- Pod 是：K8s调度的最小单位，是容器的打包盒
- 为什么我电脑上是"容器套容器"：为了在单台电脑上**快速模拟出一个多节点的 Kubernetes 集群**

## 三、describe 怎么读

（以后 Pod 起不来，第一屏看哪里？）

| 字段 | 含义 | 今天看到的值 |
|---|---|---|
| Node | 格式是“**节点名/节点 IP**”。Pod 被调度到 `cka-worker2` 这个节点；`172.19.0.4` 是这个节点在 kind/Docker 网络里的 IP。它**不是 Pod IP**，也不是你宿主机 IP。在 kind 里，`cka-worker2` 本身就是个 Docker 容器。 | 写在左边了 |
| IP | 这是 **Pod IP**，由 CNI（kindnet）分配在 Pod 网络里。集群内 Pod 之间可以用它访问；宿主机一般不能直接访问，通常用 `kubectl port-forward` 或 Service。 | 10.244.1.3 |
| Container ID | 这是 **nginx 容器实例的运行时 ID**。前缀 `containerd://` 表示它由 `cka-worker2` 节点内部的 containerd 管理，不是宿主机 Docker 的容器 ID。去掉前缀后的短 ID 是 `348915ae25eb`。 | containerd://348915ae25eb... |
| Events 四行 | 这是同一个 Pod 的四个生命周期事件，不是四个容器。顺序表示：调度成功 → 镜像可用 → 创建容器 → 启动容器。全是 `Normal`，说明正常。 | Scheduled / Pulled / Created / Started |
