## 二、案例 05：从空模板写到 210 行（约 2 小时）

主题：`Connection refused` 和 `Connection timed out` 是两种相反的故障。

**跑的六个实验**：

| # | 做什么 | 结果 |
|---|---|---|
| 3.1 | 起 `http.server` 打一次 | `HTTP 200`，服务端有日志 |
| 3.2 | `curl 127.0.0.1:9`（本机没监听） | refused，**0 ms** |
| 3.3 | `curl 网关:9`（跨主机没监听） | refused，**0 ms** |
| 3.4 | `curl 192.0.2.1`（不存在的地址） | timeout，**4000 ms** |
| 3.5 | `iptables` DROP 8080 / REJECT 8081 | **同一个端口，两种相反错误** |
| 3.6 | `tcpdump` 抓 RST | SYN → RST 间隔 **72 微秒** |

**最值钱的一段**是 3.5：同一台机器、同样"没人能连上"，只因为防火墙策略不同，
客户端看到的错误完全相反。DROP 让你以为网络不通，REJECT 让你立刻知道端口没开。

**第 4 节根因**用自己三句话写的：

- RST 是目标机器的内核发的（这次走 loopback，就是本机内核）
- 72 微秒说明有个包真的回来了
- **refused 是"等到了一个明确的否定"，timeout 是"什么都没等到"**

## 五、今天踩的坑（**这部分最值钱**）

### 1. `//` 不是 bash 注释

案例 04 里写过一次，案例 05 又写了一次。bash 只有 `#`。
而且注释不能粘在**输出块**里（`104.20.23.154//dig` 这种），输出块要能原样复现。

### 2. 输出块里混进命令

3.5、3.7 的输出块里都有我自己敲的命令行。**输出块只放输出**，命令上面有 `bash` 块。
混在一起，复制下来不能跑，别人也分不清哪行是输入哪行是输出。

### 3. 命令参数和输出对不上

命令写 `--connect-timeout 3`，输出是 `after 4000 ms`。
**案例里命令和输出必须严丝合缝**，对不上等于告诉面试官"这段是编的"。

### 4. 连不上的时候没有 HTTP 状态码

原来写"发现方式：看网页 HTTP 码"。错的——`refused` / `timeout` 都发生在**连接**阶段，
比 HTTP 还早一层。状态码是服务器回了响应之后才有的。

### 5. `source lib/common.sh` 是相对当前目录

```bash
source "$(dirname "$0")/../lib/common.sh"   # 对：相对脚本自己
source lib/common.sh                        # 错：相对你在哪
```

`$0` 是脚本被调用时的路径，`dirname` 去掉文件名留下目录，再往上退一级。

### 6. `du` 要加 `timeout`

`du -x --max-depth=1 /` 冷启动 **16 秒**，缓存后 2 秒。`-x` 挡住了跨文件系统，
但没挡住范围本身。11-15 踩过 `du -sh /` 卡死，同一个坑的不同深度。

### 7. 脚本里的 `sudo` 会卡死

`sudo lsof +L1` 在交互终端里没问题（输密码），但**非交互场景会一直等**——
cron、CI、ssh 远程执行都没有终端可以问它。真要自动化得用 `sudo -n`。

### 8. commit message 打错字

`feat: checks/dish.sh` —— 应该是 `disk.sh`。手快打错的。
